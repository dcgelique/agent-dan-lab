01 / start

What you are building

An executive asks one agent to review a branch investment proposal. That agent delegates cohort selection, calculations, and control questions to three specialists, then assembles a concise decision brief.

AgentOwnsSource
Branch Performance AnalystWhich fictional cohorts to prioritizeBranch scorecard
Investment Finance AnalystCost, annual benefit, simple paybackInvestment model
Risk and Delivery ReviewerReview gates and rollout dependenciesFictional review gates
Agent DanDelegation and decision briefConnected specialists
Prerequisites: Copilot Studio maker access to an environment with the GitHub Copilot harness, permission to create and publish agents, the ability to upload files, and available capacity. Build all four agents in the same environment. If working in teams, the owner must share the specialists with the person connecting them.

The GitHub Copilot harness is a Copilot Studio authoring experience; this lab does not require GitHub Copilot in VS Code or a GitHub repository. Interface labels and availability can vary by tenant.

Investment-Model.md 
# Fictional investment model — demo only
Source: DEMO-FINANCE-2026-09-28. Currency: PHP millions.
Benefits are annual modeled run-rate after implementation, not guaranteed returns.

Formula: cost = sum of selected cohort costs.
Formula: annual benefit = sum of selected cohort annual benefits.
Formula: simple payback months = 12 × cost / annual benefit.
Formula: low-case annual benefit = 0.75 × annual benefit.
Formula: low-case payback months = 12 × cost / low-case annual benefit.

Cohort inputs: A cost 30, benefit 8; B cost 30, benefit 7; C cost 30, benefit 5; D cost 30, benefit 4.
FULL A+B+C+D: cost 120; annual benefit 24; payback 60 months; low-case benefit 18; low-case payback 80 months.
STAGED A+B: cost 60; annual benefit 15; payback 48 months; low-case benefit 11.25; low-case payback 64 months.
ALTERNATE A+C: cost 60; annual benefit 13; payback about 55.4 months; low-case benefit 9.75; low-case payback about 73.8 months.

No discount rate, cost-of-capital estimate, NPV, IRR, validated revenue attribution, detailed site plan, or approved forecast is included. Do not call simple payback ROI.
Risk-and-Delivery-Policy.md 
# Fictional modernization review gates — demo only
Source: DEMO-RISK-2026-09-28. This is not Security Bank policy.

Before any funding release: Finance validates assumptions; Procurement validates vendor terms and pricing; Technology and Security assess integration and controls; Operations signs off on service continuity; site owners verify readiness; accountable approvers follow actual bank procedures.

Potential Wave 1: cohorts A and B, only after checks and sign-offs. Deploy in stages with operational acceptance checks. Potential Wave 2: C and D after landlord/site dependencies, risk findings, and Wave 1 outcomes are reviewed. The program sponsor owns the proposal. The executive remains the decision-maker under actual governance.

Escalate missing source data, unsupported financial claims, requests to bypass reviews, invented bank policy, and any assertion that the budget is already approved.
03 / specialist

Build the Branch Performance Analyst

  1. In Copilot Studio, select Agent on Home or Agents → New agent. Keep the GitHub Copilot harness experience and your demo environment.
  2. Name the agent Branch Performance Analyst. Set its description and instructions using the copy blocks below. Save.
  3. In Build → Knowledge, upload Branch-Scorecard.md. Describe it as the synthetic cohort scorecard.
  4. Open … → Settings → AI & behavior and turn on Allow other agents to connect. Set internal authentication under Safety & access as appropriate for the tenant. Save.
  5. In Preview, ask: “Under ₱60 million, which cohorts should go first and why?” Expect A+B, 10 branches, ₱60m, ₱15m annual modeled benefit. Publish.
Description 
Ranks the four fictional branch cohorts by service priority, growth, benefit, and readiness. Use for branch prioritization or scope changes. Does not calculate payback or approve funding.
Instructions 
You analyze only the attached synthetic branch scorecard. Each cohort contains five branches. Return selected cohort IDs, branch count, total cost, total modeled annual benefit, relevant wait and visit data, readiness, and a short rationale. For a constrained budget, select cohorts whose combined cost does not exceed it. Prefer Ready cohorts with High service priority, then higher modeled annual benefit. Mark Conditional dependencies. Identify the scorecard source ID and cohort rows. Never invent actual branch names or claim these are real Security Bank figures. Do not calculate payback or approve spending. If source retrieval fails, state that you cannot verify the selection.

06 / orchestration

Connect the Agent Dan

  1. Create Agent Dan in the same environment. Paste the description and instructions below. Save.
  2. On Build, select Connected agents. Add the three published specialists one at a time. Give each connection the same narrow description used above; select Connect. Check all three appear in the components panel.
  3. In … → Settings → Greeting & prompts, optionally set: “I can compare fictional branch investment options and prepare a decision brief. What budget would you like to assess?” Save.
  4. Open Preview and run the tests in the next section. Publish the executive agent if participants need access outside authoring Preview.
Description 
Executive decision support for fictional branch modernization investments. Coordinates branch, finance, and risk specialists; presents options, assumptions, and approval questions. Never makes a funding decision.
Instructions 
You support an executive evaluating a fictional branch-modernization proposal. All data and review gates are synthetic demo content, not Security Bank data or policy.

For a request about where to invest, ask Branch Performance Analyst for a cohort selection and evidence. Ask Investment Finance Analyst to calculate the exact selected cohort IDs, and ask Risk and Delivery Reviewer for review gates and delivery dependencies. If the first finance call happens before cohort selection, call Finance again with the final cohort IDs. Reconcile branch count, costs, and benefit against the returned source data. If a specialist is unavailable or findings conflict, surface the gap rather than inventing an answer.

For follow-up budget limits, request a new cohort selection under the new limit and new finance calculations for that selection. Distinguish the full program from the immediate tranche and deferred work. Annual benefits are modeled run-rate after implementation. Simple payback is not ROI, NPV, or IRR.

Reply with a concise decision brief: recommended next step; selected cohorts and branch count; budget now and deferred; modeled annual benefit; simple payback and low-case sensitivity; selection rationale; gates and owners; assumptions and missing evidence; decision requested. Identify synthetic source IDs. No real approval authority or actual bank policy is supplied. Never say funding has been approved or controls cleared. If asked to approve, offer a draft for human review instead.
Routing note: connected-agent descriptions guide orchestration; they do not force a fixed call order. Judge the result and inspect the trace. The executive agent should disclose a missing specialist answer.

08 / workflow hands-on

Create a draft decision record

Add a workflow tool to Agent Dan. The user reviews the draft fields and explicitly confirms creation. The workflow checks the confirmation input, writes one Draft / For human review row in Dataverse, and returns a record ID. It never approves or releases funds.

Allow 25–35 minutes. This step needs permission to create a Dataverse table and workflow in the same demo environment. Use fictional data only. If you cannot create a table, complete the multi-agent exercise through Step 07 and review this pattern with your facilitator.

8A · Import the sample table

  1. Download Investment-Decision-Draft-Sample.xlsx
  2. In Power Apps → Tables → New table → Create with external data → File (Excel, .CSV), upload the workbook. Name the new Dataverse table Investment Decision Draft.
  3. Review the preview before saving. Use Draft Name as the primary name column, set the five cost/benefit/payback columns to Decimal number, and keep Unresolved Gates as multiline text if offered. Leave the other columns as text. Save the table and inspect the imported records.
  4. Record the actual Dataverse column names shown in your environment. The workflow designer can display friendly names while its underlying schema names differ; map by the visible columns, not an assumed prefix.

If “Create with external data” is unavailable in your tenant, create a blank Investment Decision Draft table with the same workbook headers and import the file into that table. “Decision Stage” is the workbook's draft label; the workflow sets it to Draft / For human review rather than accepting an agent-supplied value.

8B · Build the workflow

  1. In Copilot Studio select Workflows → New workflow. Name it Create Investment Decision Draft — Demo. Use the trigger When an agent calls the flow.
  2. Add the inputs in the table below. Use numbers for numeric inputs if your designer offers that type; otherwise use text and validate/convert before writing to Decimal columns. Add UserConfirmed as Boolean if available, or text with the exact value YES for this exercise.
  3. Add a Condition immediately after the trigger: continue only if UserConfirmed is true (or equals YES in the text variant). A false, missing, or unexpected value follows the No branch. This guard is part of the workflow; the agent's instruction alone is insufficient.
  4. On the Yes branch, add Dataverse Add a new row for Investment Decision Draft. Map input fields to the matching columns. Set Draft Name to a recognizable scenario label and set Decision Stage inside the workflow to the literal Draft / For human review. Do not accept a Decision Stage input from the agent.
  5. After the row is created, add Respond to the agent with Outcome=DraftCreated, RecordId from the Dataverse row ID, and DecisionStage=Draft / For human review. On the No branch, add Respond to the agent with Outcome=Cancelled, blank RecordId, and DecisionStage=No record created.
  6. For each response action, open its networking settings and set Asynchronous response = Off. Save, test both branches, then Publish. Keep the workflow's response within the documented 100-second action limit.

8C · Attach the tool and update the executive agent

  1. Open Agent Dan → Build → Tools → Add a tool → Workflows. Select the published Create Investment Decision Draft — Demo. If it does not appear, check trigger, response actions, real-time setting, publication, environment, and permissions.
  2. Set the workflow's tool description with the copy block below. Add the instruction block after the existing executive agent instructions; save and publish the agent for channel use.
Workflow tool description 
Creates one fictional investment decision draft in Dataverse only after the user reviews the displayed fields and explicitly confirms creation. Returns DraftCreated with a record ID or Cancelled with no row. Never approves or releases funds.
Add to executive agent instructions 
When the user asks to record or prepare a draft decision, show the exact fields that would be saved: scenario ID (use a new unique ID for the live test), selected and deferred cohorts, budget now and deferred (PHP millions), annual modeled benefit, simple and low-case payback months, and unresolved review gates. Ask: “Create this draft decision record with these fields?” Do not call the Create Investment Decision Draft workflow until the user gives a clear affirmative answer to that specific reviewed draft. If the user changes a field, show the revised draft and ask again. A refusal, ambiguity, or silence is not confirmation. Pass UserConfirmed=true (or the exact text YES, depending on the configured trigger) only after that confirmation. Treat a Cancelled response, failed tool call, or missing RecordId as no record created. After a DraftCreated response, report only the returned RecordId and draft decision stage; never claim approval or release of funds. Do not repeat a successful create call unless the user explicitly asks for another draft.
